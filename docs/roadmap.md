# 개발 과제

[프로젝트 홈](../README.md) · [문서 모음](README.md) · [날짜별 변경](../CHANGELOG.md)

2026-10-07 코드 반영 기준입니다. 아래는 완료 선언이나 일정 약속이 아니라 **구현된 범위와 남은 과제**를 구분한 목록입니다. 우선순위는 정확성, 그다음 가독성입니다.

## 우선순위

1. **사람이 검수한 정답 확보:** 사용자 곡의 도입부 하이햇 누락 같은 오류 구간을 10~30초 단위로 검수하고 개발에 쓰지 않은 곡을 별도 평가합니다.
2. **분리 손실과 채보 오류 구분:** 같은 원곡/구간/정답으로 SAM 순차·독립 추출을 비교합니다. 모델 간 동의만으로 정답을 확정하지 않습니다.
3. **악기별 개선 검증:** 하이햇 개방 구분·분리 아티팩트, 기타 배음/안쪽 화음, 피아노 전용 모델, 베이스 저음, 신디 지속음, 보컬 코러스를 실제 연주로 평가합니다.
4. **악보·오디오 대조:** 이용 권한이 있는 MusicXML을 기준으로 스타일 재조판 → 오디오 정렬 → 차이 검토를 확장합니다. 출처/권한을 확인한 악보 검색 자동화는 아직 없습니다.

원본 MusicXML을 보존하는 것과 모든 표기를 편집할 수 있는 것은 다릅니다. PDF의 숫자/리듬 후보를 보존하는 것도 원본 PDF의 무손실 복원을 의미하지 않습니다.

## 연구 결과의 웹 연결

- STRUM·CREPE·YourMT3+는 연구용 독립 비교 경로입니다. 전체 기본 모델을 대체하지 않습니다.
- 독립 모델이 제안한 하이햇 후보의 웹 비교·개별 적용은 별도 구현 과제입니다.
- 일정 BPM 적합·반속/배속·구간 변화 진단은 구현했지만 템포 지도와 정밀한 길이/쉼표의 자동 기보 반영은 남아 있습니다.
- 일반 정확도 향상이 입증되지 않은 보강/디코더 후보는 기본 설정에 적용하지 않습니다. 기각 결과도 [연구 기록](README.md)에 유지합니다.

## 운영·배포 과제

- 인증·사용자별 권한/저장소, 작업 큐·재시도, 보관/삭제 정책, 요청·용량 제한.
- 문서 처리 격리·악성 문서 방어, HTTPS 프록시, 장애·디스크/GPU 모니터링.
- 서버 잠금 파일과 PDF 기본 의존성의 동기화. 현재 `pdfplumber`는 [PDF 추가 설치](setup.md#pdf-tools)로 보완해야 합니다.
- 외부 모델/도구의 사용 조건과 공개 서비스 배포 의무 확인.
- 회사 서버 실제 반영 및 GPU 품질 검증은 권한이 있는 운영자와 별도 진행.

세부 테스트 범위는 [테스트 안내](testing.md), 당시의 개선/회귀 수치는 [날짜별 연구 문서](README.md)를 참고하세요.
