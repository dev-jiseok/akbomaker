## 업로드와 작업 관리

- 파일 선택·드래그 앤 드롭과 업로드 전 미리듣기를 지원합니다. 영상의 오디오는 FFmpeg로 추출하고 YouTube 개별 영상은 yt-dlp로 받습니다. [입력 형식·제한](../README.md#지원-입력)을 확인하세요.
- 작업 진행률·중단·새로고침 후 복원을 지원하며, 이 브라우저의 최근 프로젝트는 최대 20개까지 표시합니다.
- 긴 음원의 SAM 처리는 기본 20초 구간과 2초 겹침을 사용합니다. 구간 길이는 `SAM_CHUNK_SECONDS`로 설정합니다.
- 완료 후 악기별 WAV·파형·솔로·음소거·볼륨·재생 위치로 비교합니다. 마지막 잔여 음원은 순차 분리에만 있습니다.
- 샘플 작업실의 WAV·MIDI·MusicXML은 직접 합성한 예시이며 실제 SAM 분리 성능의 근거가 아닙니다.

## 악기별 경로

| 악기 | 현재 채보 경로 | 기본 표기와 검토 대상 |
| --- | --- | --- |
| 보컬 | CPU pYIN 기본음 추적, 비브라토 안정화, 무음·재발음 구분 | 단일 멜로디 보표 + 공통 가사. 코러스/겹친 보컬의 주선율 선택은 미해결 |
| 베이스 | 저음용 긴 분석 창의 pYIN, 필요 시 ‘화음 포함’ Basic Pitch | TAB 위 + 오선 아래. 5현 저음/튜닝·카포·실제 운지 확인 |
| 기타 | 음역·최소 음 길이·온셋 기준을 적용한 다성 Basic Pitch | TAB 위 + 오선 아래. 배음/잔향·줄 배정 검토 |
| 피아노 | 건반 음역의 다성 Basic Pitch | 대보표, 음표별 손 배정. 손가락/독립 성부·페달 인식은 미구현 |
| 신디 | 지속음을 고려한 다성 Basic Pitch | 대보표 또는 단일 리드 보표 선택. 음색/패드 잔향 검토 |
| 드럼 | 독립 대역 온셋 또는 선택 설치한 ADT_STR | 타악기 5선·성부·빔. 경량 검출기는 3종 추정으로 스네어/심벌 분류 한계가 큼 |

- 보컬·베이스의 ‘화음 포함’은 다시 채보할 때 적용합니다. 전체 악기 재채보는 각 악기의 기본 방식을 사용합니다.
- 건반의 `악보 직접 수정 → 건반 악보 형식`은 음정·길이·MIDI를 유지한 채 표기만 바꿉니다. 경계음(기본 C4) 미만은 왼손으로 배정하며 음표별 수동 지정이 우선합니다.
- 공통 가사는 단일 보표 아래, TAB/대보표에서는 아래쪽 보표 밑에 표시합니다. 가사 타임라인에서 별도로 검토·적용해야 하며 멜로디 채보가 노랫말을 생성하지는 않습니다.
- 신디의 `지속음 보강 (실험)`은 선택 후 재채보해야 적용합니다. 기타·피아노에는 검증 회귀가 있어 공개 API에서 이 보강 방식을 허용하지 않습니다.

새 엔진·방식 정보는 악보 JSON과 파트 메타데이터에 남습니다. 새 기능이 추가됐다는 이유만으로 기존 프로젝트의 음표나 원본을 자동 덮어쓰지 않습니다.

## SAM 분리 방식

| 선택 | 입력 방식 | 유의점 |
| --- | --- | --- |
| `sequential` · 기본 | 앞 단계의 결과를 뺀 잔여음에서 다음 악기 추출 | 앞 단계의 과도한 제거가 뒤 악기로 전파될 수 있음 |
| `independent` · 선택 | 여섯 악기 모두 같은 준비된 원본의 복사본에서 추출 | 결과 간 같은 소리가 겹칠 수 있어 합산 보존·잔여 음원을 제공하지 않음 |

순차 분리는 `extract`를 한 번만 계산합니다. 중간 결과는 48kHz 모노 부동소수점 WAV로 저장해 단계별 클리핑을 피합니다.

```python
residual = audio.copy()
for inst in ["vocal", "bass", "drums", "synthesizer", "guitar", "piano"]:
    target = extract(residual, inst)
    outputs[inst] = target
    residual = residual - target
# sum(outputs.values()) + residual ≈ audio
```

모든 곡에 여섯 악기가 존재하는 것은 아니고, 비슷한 음색을 모델이 혼동할 수 있습니다. 해당 악기의 소리가 매우 작으면 화면에 안내합니다.

독립 추출은 새 업로드에서 선택하며 믹서는 원본으로 시작합니다. 분리 결과는 한 악기씩 비교 청취하세요. 분석 전용 업로드와 독립 분리를 함께 선택할 수는 없습니다. 실제 GPU 분리 품질 개선은 아직 검증하지 않았으며, 기존 프로젝트의 재분리·악보 교체도 자동 실행하지 않습니다.

SAM 모델 승인·GPU 설정은 [설치 안내](setup.md)를, 같은 입력의 순차/독립 비교 명령은 [연구 기록](research/2026-10-06-audio.md#stage-8)을 참고하세요.

## 드럼 엔진 선택

드럼 파트에서 엔진과 입력(`분리된 드럼 / 원본 전체 음원`)을 고른 뒤 다시 채보합니다. `분리 없이 원본만 분석`으로 올린 드럼 녹음도 원본 입력을 선택하면 SAM/GPU 없이 채보할 수 있습니다. 다른 파트를 분리 완료로 표시하지는 않습니다.

| 엔진 | 동작 | 주의점 |
| --- | --- | --- |
| 자동 | 운영자가 워커를 설정한 경우 전용 AI 사용 | 잘못된 설정·실행 실패를 경량 검출로 숨기지 않음 |
| 전용 AI | ADT_STR 한 번 분석 | 곡에 따라 누락·종류 혼동이 남음 |
| 교차검증 AI · 실험 | 같은 모델의 청크 문맥을 바꿔 3회 분석, 2회 이상 일치한 종류·시각 채택 | 독립 모델 3개의 신뢰도가 아님. 약한 타격 누락 가능 |
| 보강 AI · 실험 | 피크 보정 1회 ADT + 겹치지 않는 경량 하이햇 후보 추가 | 누락 감소와 오인식 증가가 함께 나타남 |
| 경량 검출 | 독립 대역 온셋 기반 | 전용 모델 없이 동작하지만 3종 추정의 한계가 큼 |

전체 믹스를 직접 채보하면 다른 악기를 드럼으로 오인할 수 있습니다. 교차검증 모드는 피크 보정+greedy+3회, 보강 모드는 환경변수와 무관하게 1회로 고정합니다. `constrained`·`guarded` 디코더는 연구용이며 정확도 개선 기본값으로 권장하지 않습니다.

### 타격 매핑과 후처리

- ADT의 26종 번호는 GM과 다릅니다. 예를 들어 모델 44/46/48은 오픈 하이햇/크래시/라이드로, 먼저 GM 46/49/51로 변환합니다.
- 편집기에서는 11종으로 정리합니다. 페달 하이햇은 킥과 아래 성부, 사이드스틱은 스네어 위치의 x음표입니다. 탐·심벌 변종 통합과 미지원 타악기 수를 기록하고 미지원 타격을 스네어로 강제 변환하지 않습니다.
- 새 자동 채보의 표기 길이는 다음 타격/박 경계까지만 유지해 불필요한 타이를 줄입니다. 수동 입력·가져온 악보의 길이는 바꾸지 않습니다.
- 전용 모델 경로에는 `conservative-kick-evidence-v1`이 적용됩니다. 충분한 저음 타격 근거가 있는 경우에만 약한 킥 후보를 보수적으로 제외하며, 하이햇을 대신 추가하지 않습니다. 작은 실제 킥을 지울 위험과 실제 사용자 곡의 하이햇 누락은 남아 있습니다.

### 원시 결과와 제한

`AI 원본 타격·검토 데이터`에서 다음 파일을 받을 수 있습니다.

| 파일 | 보관 내용 |
| --- | --- |
| `drums.raw.mid` | 박자 격자 이전 GM 타격과 미지원 타악기. 보강 모드에서는 보완 전 모델 결과, 교차검증에서는 합의 통과 후 결과 |
| `drums.transcription.json` | 원본 타격, 모델·패키지 버전, 청크별 원시 토큰, 통합/미지원 및 불완전 출력 경고 |
| JSON의 `recovery`, `score_events`, `kick_evidence` | 추가 타격·최종 악보 입력·킥 제외 근거를 원본과 분리 보관 |
| JSON의 `runtime.consensus` | 3회 전체 후보·투표·보류 타격. 합의가 정답 확률은 아님 |

토큰은 시작 시각·악기·세기 묶음으로 엄격하게 읽습니다. 잘못된 토큰 뒤의 음정을 이전 시각에 붙이지 않습니다. 경량 엔진으로 재채보하면 이전 AI 파일을 현재 결과로 다운로드/ZIP에 포함하지 않습니다.

실행 제한은 1회 분석 10분, 3회 교차검증 30분입니다. 실행 중 취소는 추론 반환 뒤 반영됩니다. 1차 CPU 측정은 12초 녹음당 약 6–27초(프로세스 시작 포함)였으며 긴 곡의 시간을 보장하지 않습니다. CUDA 사용 시 별도 환경의 메모리를 확인해야 하며 SAM의 GPU 선택 정책은 이 프로세스에 적용되지 않습니다.

## 선택 설치: ADT_STR

`backend/drum_worker.py`와 `scripts/transcribe-drums.py`는 [ADT_STR 공식 추론 API](https://github.com/pier-maker92/ADT_STR)를 별도 프로세스로 호출합니다. macOS arm64 CPU 실제 체크포인트 추론·무음·공개 녹음 비교를 수행했지만, 연결 성공이 곡별 악보 정확도를 보증하지는 않습니다.

다음 명령은 저장소 루트에서 운영자가 명시적으로 실행합니다. 별도 Python 3.11 환경을 사용하며 요청 처리 중 패키지/체크포인트를 설치하지 않습니다.

```sh
git clone https://github.com/pier-maker92/ADT_STR.git .data/drum-runtime/ADT_STR
git -C .data/drum-runtime/ADT_STR checkout --detach 77dbef225e7029478ebfb916f20c7a00274f0f12
uv venv --python 3.11 .data/drum-runtime/.venv
uv pip install --python .data/drum-runtime/.venv/bin/python -r requirements-drum.txt
HF_HOME=.data/drum-runtime/hf-cache .data/drum-runtime/.venv/bin/python scripts/prepare-drum-model.py
```

| 설정·검사 | 내용 |
| --- | --- |
| 다운로드 고정 | `Pierfrancesco/adt-str`, revision `a33c5c6b191a4ca1e0f6dc22140947485eb36ce8`, `setting-tau-0.8`만 다운로드·SHA-256 기록. 약 290MB |
| `AKBO_DRUM_MODEL_DIR` | 다운로드 루트가 아닌 **`setting-tau-0.8` 폴더**를 지정 |
| 나머지 경로 | [`.env.example`](../.env.example)의 `AKBO_DRUM_*` 참고 |
| 추론 전 검사 | HF 오프라인 모드, 매니페스트 체크섬·소스 커밋 검증 |
| 오디오 입력 | TorchCodec 없이 soundfile → tensor API |
| `/api/health` | `drum_engine.paths_ready`는 파일 설정 검사일 뿐 실제 추론 성공 보증이 아님 |

**이용 조건:** 공식 소스는 CC-BY-SA-4.0이며, 연구 당시 확인한 [HF 모델 카드](https://huggingface.co/Pierfrancesco/adt-str)는 별도 가중치 라이선스를 명시하지 않았습니다. 가중치 배포·공개/상업 서비스 적용 전 사용 조건을 확인해야 합니다. 가중치·외부 소스·평가 음원은 Git에 포함하지 않습니다.

## 박자와 입력 보전

재채보 전에 BPM·박자·첫 박 위치와 분리 음원의 상태를 확인하세요. `BPM · 박 위치 분석`은 일정 격자 적합, 반속/배속 후보, 구간별 주기 변화와 누적 밀림 근거를 제시합니다.

- 일정한 박열이 충분할 때만 별도 정수 BPM 비교 버튼을 제공합니다. 불규칙하거나 짧은 구간에는 후보를 강제하지 않습니다.
- BPM·마디 첫 박·기존 악보를 자동 변경하지 않습니다. 주기성·잔차는 정답 다운비트나 정확도 점수가 아닙니다.
- 변속 템포 지도·셋잇단음표의 자동 채보 반영은 아직 남은 과제입니다.

입력 보전은 심한 스테레오 위상 상쇄만 방어합니다. 업로드 준비와 pYIN·경량 드럼·ADT 공유 입력 경로는 두 채널 평균 전력이 강한 원본 채널의 1% 이하인 경우를 검사합니다. 채보 공유 가드는 원본 채널 RMS `1e-5` 이상일 때만 해당 채널을 선택합니다.

정상 입력의 기존 평균·리샘플·정규화 순서는 유지하고, 모노/서라운드에서 임의 채널을 고르지 않습니다. `audio_preprocessing`·`channel_preprocessing`에 근거를 기록하며 반대 채널의 독립 연주가 빠질 수 있음을 경고합니다. 이미 모노로 저장되며 손실된 음원을 복구하거나 일반적인 악기 인식률을 높이는 기능은 아닙니다.

<a id="evidence"></a>

## 채보 근거와 구간 비교

여섯 악기 모두 실제 채보 시 `{instrument}.notes.json`을 저장합니다. 화면의 `채보 당시 음표 데이터 (수정 전)`에서 받을 수 있습니다.

| 포함 | 포함하지 않음 |
| --- | --- |
| 악기 후처리 후, 박자 격자·시작 오프셋 적용 전 음표 | 이후 수동 수정·악보 가져오기 |
| 입력 SHA-256, 엔진/모델 출처, 초 단위 시작·종료, 실음 MIDI, 강도 | 강도를 신뢰도/정답 확률로 해석한 값 |
| 추론·악보 생성 성공 후 교체된 근거 | 알려진 작곡 음표를 보여 주는 샘플을 실제 추론으로 표시 |

음표 수·유한값·음원 범위·파일 크기를 검사하며 실패/취소 시 이전 결과를 보존합니다. 옛 프로젝트에 근거 파일이 없으면 링크나 ZIP 항목을 만들지 않습니다.

### 화면에서 비교하기

1. 실제 음원 프로젝트에서 악기를 선택하고 `구간 비교 열기`를 누릅니다.
2. 원곡/분리음의 4·8·16·30초 구간을 같은 시작점에서 비교합니다. 0.5·0.75·1배속과 반복을 지원합니다.
3. `인식한 음표` → `최근 자동 생성 악보` → `현재 저장된 악보`를 나란히 봅니다. 미저장 초안은 대상이 아닙니다.
4. 음표를 선택하고 `이 위치의 악보 수정`으로 이동합니다. 채보 당시 BPM·시작 오프셋·변박을 반영하며 자동 수정/저장하지 않습니다.

색 차이는 오답 표시가 아니며 간이 합성음은 실제 악기 음색/분리 품질의 증거가 아닙니다. 지원하지 않는 드럼 GM은 보존하고 임의 킥으로 재생하지 않습니다. 플레이어 간 재생 소유권을 공유하고 파트/구간 변경·재채보·접기·탭 숨김 시 검토 재생을 중단합니다.

읽기 전용 API: `GET /api/jobs/{job_id}/transcription-review/{instrument}?start=0&seconds=8`

입력 SHA-256·악보 revision·설정 불일치, 파일 변경·재채보 실패·큰 기록은 거절합니다. 조회가 추론이나 악보 쓰기를 실행하지 않습니다. 비교하는 것은 모델 logits가 아닌 후처리 음표이므로 모델/후처리 오류를 완전히 분리할 수는 없습니다. 해시도 전체 SAM 생성 이력이나 정확도 인증은 아닙니다.

<a id="review-cases"></a>

## 검수 사례와 회귀 비교

`구간 비교 열기 → 현재 구간 검수 시작`에서 입력 해시·출처와 세 단계의 구간 음표를 고정합니다. 이후 재채보/편집해도 기존 검수 자료는 바뀌지 않습니다.

1. 누락·추가·음정/종류·시작·종료 등 오류 메모를 남깁니다. 메모 자체가 정답 음표는 아닙니다.
2. 비어 있는 참조 음표에 직접 입력하거나 고정 단계의 음표를 명시적으로 복사합니다. 복사 출처 `seed_layer`를 보관하며 자동 검수 완료로 처리하지 않습니다.
3. 검수자·근거·전체 구간 확인을 **초안 저장한 뒤 별도 확정**합니다. 이름은 인증된 신원이 아닙니다.
4. 확정 참조와 세 단계의 ±50ms 음정/원시 GM 온셋 지표, 드럼 외 종료 길이 진단을 확인하고 JSON을 내보냅니다. 빈 참조를 완벽한 점수로 표시하지 않으며 JSON에 음원은 들어가지 않습니다.

| 저장·안전 조건 | 범위 |
| --- | --- |
| 위치 | `.data/<job>/review-cases/<instrument>/`, 원본 악보·음원과 분리 |
| 한도 | 악기당 32사례, 사례당 참조 1,500개·메모 300개, 요청/파일 2MB |
| 충돌·복구 | revision 검증·원자적 교체, 최근 최대 3개 이전 상태(영구 이력 아님) |
| 실행 전제 | 단일 서버 프로세스 잠금. 경로·심볼릭 링크·중복 JSON 키·비유한 값·동시 재채보 방어 |
| 과거 초안 | 입력/악보 변경 후 새 확정은 거절. 읽기·초안 저장·백업과 기존 확정 결과 내보내기는 가능 |

브라우저 임시본은 서버 revision이 같을 때만 명시적으로 복원합니다. 입력 중인 음표/메모는 먼저 목록에 적용해야 저장·백업됩니다.

API: `/api/jobs/{job}/review-cases/{instrument}`의 GET·POST, `/{case_id}`의 GET·PUT, `/{case_id}/export`의 JSON 다운로드. 생성/확정은 본문 크기 검사 후 작업 스레드와 같은 작업 잠금 안에서 파일을 재검증하며 모델을 호출하지 않습니다.

동일 입력으로 만든 새 후보를 검수 사례와 비교하는 명령:

```sh
.venv/bin/python scripts/evaluate-review-case.py \
  --case /path/to/reviewed-case.export.json \
  --prediction /path/to/bass.notes.json \
  --audio /path/to/the-exact-source-bass.wav \
  --output .data/new-review-regression.json
```

**동일 WAV 바이트**와 연결된 음표 파일만 받습니다. 분리음이 바뀐 결과를 해시를 우회해 비교하지 않습니다. 기존 출력은 덮어쓰지 않고 참조·후보·음원·평가 코드 해시와 지표 차이를 보관합니다. 이는 선택한 검수 구간의 진단이지 분리 방식 평가·학습·곡 전체 정확도·우승 모델 판정이 아닙니다.
