# 테스트와 검증 범위

[프로젝트 홈](../README.md) · [문서 모음](README.md) · [변경 이력](../CHANGELOG.md)

**기능 테스트 통과 ≠ 모델 실행 성공 ≠ 실제 음악의 정확도 개선.** 아래 검사를 구분해 기록합니다.

## 일반 개발·CI 검사

개발 의존성을 [설치](setup.md#development)한 뒤 저장소 루트에서 실행합니다.

```sh
npm run build
npm test
npm run test:api
```

[GitHub CI](../.github/workflows/check.yml)는 Node 22, Python 3.11, FFmpeg·libsndfile 환경에서 빌드와 프런트/백엔드 테스트를 실행합니다. 선택형 ML 런타임·GPU·비공개 악보가 필요한 검사는 일반 CI와 분리합니다.

### 주요 회귀 검사

| 영역 | 확인하는 계약 |
| --- | --- |
| 업로드·처리 | URL/크기 제한, 오디오 범위 요청, 작업 중단, 처리 오류, WAV·MIDI·MusicXML·ZIP 연결 |
| 분리 | 순차 추출 호출 수, 합산 보존, 구간 끝 커버리지. 일반 CI에서는 모델만 대체 |
| 편집·저장 | 수정본/원본 분리, 비파괴 미리보기, revision 충돌, 입력 검증, 영구 undo/redo, 저장 실패 원자성 |
| TAB·가사 | 줄/프렛/튜닝·카포·실제 음정, 같은 줄 겹침 거절, 화음 운지, 미배정 음 보존, LRC/오프셋/가사 복사 |
| 박자·기보 | 여섯 박자의 성부별 마디 길이, 6/8의 3+3 빔, 변박을 가로지르는 타이·가사, 점음표 템포, MIDI·600마디 한도 |
| MusicXML 가져오기 | 네임스페이스/MXL, 음정·타이·운지·가사 왕복, XML 엔티티/압축 경로/크기 제한, 안전한 편집 잠금 |
| PDF·원본 보존 | 업로드/미리보기/대기열, OMR 성공·취소·실패, 원본/결과 해시, 스타일 전후 음악 내용 비교 |
| PDF TAB | 숫자 범위·제외 사유·수동 보정, 리듬 후보의 원본/박자/revision 일치, 초안·프로젝트 트랜잭션, 재시도 시 편집본 보존 |
| 연주 기호·구조 | 안전한 연결 쌍·오선/TAB 동시 반영, 구조 이상 표시, 못갖춘마디·다성부 등 예외, 입력 XML 불변 |
| CPU 분석 | 실제 클릭 BPM/무음 거절, 분석 전용 SAM 미호출, 가사 초안 실패 시 기존 자료 보존, 전체 파트 적용 |
| 악기별 경로 | 대보표/손 배정·빈 보표 왕복, 기존 클라이언트 호환, 드럼 동시 타격/8·16비트, 워커 성공/오류 계약 |
| 화면 | 가사/재생 시간 유지, 메모 합치기, 미저장 이탈 보호, 오래된 비동기 응답 거절, 지원 범위 표시 |

가져온 MusicXML의 음악 데이터 보존을 검사해도 원본 PDF의 누락·오인식이 해결됐다는 뜻은 아닙니다. 모의 OMR/모델의 계약 검사도 실제 인식 품질을 측정하지 않습니다.

## 선택형 실제 모델·GPU 검사

필요한 승인·의존성·체크포인트가 준비된 환경에서만 명시적으로 실행하세요. 이 명령들은 일반 테스트의 대체물이 아닙니다.

| 검사 | 조건 | 측정 범위 |
| --- | --- | --- |
| 실제 SAM | 승인된 모델 + CUDA GPU + 서버 런타임 | 합성 4초 음원의 여섯 단계 실행·길이·유한 값·WAV·합산 보존 |
| 실제 ADT | [별도 드럼 환경](audio-engines.md)과 로컬 모델 | CPU 모델/워커 실행·무음·출력 계약 |
| 실제 pYIN 채널 비교 | 로컬 CPU 분석 의존성 | 명시적인 실제 단선율·채널 입력 회귀 |
| 실제 PDF 리듬 | 지정된 비공개 베이스 PDF 두 개 | 알려진 첫 4마디의 수동 판독과 자동 후보 비교 |

```sh
RUN_SAM_GPU_TESTS=1 .venv/bin/python -m pytest backend/tests/test_gpu_integration.py -v
RUN_ADT_MODEL_TESTS=1 .venv/bin/python -m pytest backend/tests/test_drum_model_integration.py -v
RUN_MELODY_MODEL_TESTS=1 .venv/bin/python -m pytest backend/tests/test_audio_channels.py -v
```

실제 PDF 검사는 이용 권한이 있는 원본 디렉터리를 지정합니다. 파일이 저장소에 포함되어 있지는 않으며 테스트가 요구하는 이름/해시는 [테스트 파일](../backend/tests/test_pdf_tab_rhythm.py)에서 확인할 수 있습니다.

```sh
AKBO_PRIVATE_BASS_PDF_DIR='/path/to/authorized-bass-pdfs' \
  .venv/bin/python -m pytest backend/tests/test_pdf_tab_rhythm.py -q
```

기존에 RTX 3090 24GB에서 SAM base의 합성 음원 스모크 테스트를 통과했습니다. 첫 실행에 모델 다운로드가 발생할 수 있으며, 이 결과는 실제 곡의 악기별 분리·채보 정확도 평가를 대체하지 않습니다.

이전의 누적 테스트 개수는 [2026-10-07 악보 검증 기록](research/2026-10-07-score-import.md)에 단계별로 보관합니다. 오래된 검사 수를 현재 기능 수나 정확도 점수로 비교하지 마세요.

### 화면·실제 데이터 확인의 한계

- 자작 샘플/6파트 MusicXML로 TAB 우선, 드럼 연결선, 대보표/손 전환, 가사, 6/8·변박·재생 강조를 확인했습니다.
- 원본 보존 프로젝트에서 프렛·드럼·가사·연주 기호 저장/재열기/실행 취소, 스타일 비교와 가로 넘침을 점검했습니다.
- 실제 베이스 PDF의 검수 초안 저장·재개, 리듬 후보 읽기/적용, 원본 첨부 해시를 확인했습니다.
- 일부 과거 네이티브 모바일 캡처는 빈 이미지여서 시각 검수 근거로 쓰지 않고 DOM 배치·실제 SVG로 확인했습니다.
- 자작 합성 발화의 Whisper CPU INT8 단어/시간 출력은 확인했지만 실제 노래의 가사 정확도 검증은 아닙니다.
- 이 검증은 회사 서버에 배포하거나 기존 사용자 프로젝트를 덮어쓰는 작업과 별개입니다.
