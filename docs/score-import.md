## 어떤 경로를 선택하나요?

| 가지고 있는 파일·목적 | 선택할 경로 | 확인할 점 |
|---|---|---|
| MusicXML/XML/MXL, 음을 그대로 두고 스타일 변경 | `원본 유지 프로젝트 열기` | 표기 구조를 유지하며 지원 범위만 수정 |
| PDF·이미지의 일반 오선/드럼 | 로컬 Audiveris 인식 후 원본 대조 | 인식 초안이며 누락·오인식 가능 |
| 문자·선이 살아 있는 기타/베이스 TAB PDF | `PDF TAB 숫자 검토` | 줄·프렛·리듬 검수 후 TAB 단일 보표 생성 |
| 제한된 오선+TAB 벡터 PDF | TAB 검수의 리듬 후보 읽기 | 마디별 대조 후 적용, 자동 완성 아님 |
| 간단한 MusicXML을 기존 격자로 다시 편집 | 고급 16분음표 격자 변환 | 원본 성부·조표·레이아웃 유지 경로가 아님 |

**PDF의 보존 기준은 인식·검토 후 생성된 MusicXML입니다.** 원본 PDF를 무손실 구조화한다고 보증하지 않습니다. 스타일 변환은 인식 오류를 고치지 않으며, 원본과의 비교가 필요합니다.

## MusicXML 원본 유지

1. 2MB 이하 MusicXML/XML/MXL을 올리고 파트·악기를 선택합니다. 홈 아래 가져오기에서도 같은 기능을 열 수 있습니다.
2. `원본 유지 프로젝트 열기`로 별도 악보 프로젝트를 만듭니다. 음원이 없어도 되며 분리 음원을 만들어 낸 것처럼 표시하지 않습니다.
3. 먼저 스타일·출력 화면이 열립니다. 편집이 필요할 때만 `틀린 부분 수정하기`를 누릅니다.
4. 합주용/기본/큰 악보와 한 줄 2/4마디 배치를 고르고 저장·출력합니다.

처음 업로드한 파일은 바이트 그대로 따로 보관합니다. 여러 파트 중 선택한 한 파트만 화면에 표시·편집하며, 나머지도 전체 작업 MusicXML과 원본에 남습니다.

음악 데이터의 기준은 원본 MusicXML이며 **16분음표 격자로 변환하지 않습니다.** 스타일만 바꾸면 음정·TAB·리듬·성부·보표·조표·잇단음표·반복·빔·페달·가사를 유지합니다. 양손 유니즌·같은 음의 다른 줄을 합치거나 운지를 자동 재배정하지 않습니다. 뷰어가 모든 기호를 똑같이 그리는 것은 아니므로 표시 결과도 비교하세요.

`원본 표기 유지 · 스타일 미리보기`는 저장 없는 레이아웃 전용 경로입니다. MusicXML 다운로드·인쇄/PDF 저장은 가능하지만, 저장·음표 수정은 `원본 유지 프로젝트 열기`를 사용합니다. 두 경로 모두 복잡한 표기를 조용히 삭제하거나 격자로 바꾸지 않습니다. 제목·저작자·저작권 텍스트는 XML에 유지하며, 외부 이미지·링크/활성 콘텐츠는 미리보기에서 제외하고 경고합니다.

## 원본 보존 편집기

마디·음표 목록에서 선택하여 수정합니다. 실행 취소/다시 실행, 변경 전 비교, 업로드 원본·현재 MusicXML 다운로드와 저장 악보 인쇄/PDF를 지원합니다.

| 악기 | 직접 수정할 수 있는 항목 | 안전 조건 |
|---|---|---|
| 보컬 | 음명·변화음·옥타브, 쉼표에 음표 넣기·동시음 추가·음표를 쉼표로 변경, 제한된 길이, 가사 | 연결 음표는 기능별 잠금, 뒤 음표의 시작 유지 |
| 기타·베이스 | 같은 음의 다른 운지, 음정을 바꾸는 줄·프렛, 쉼표/동시음, 가사 | 명시된 튜닝·카포·이조 사용; 오선/TAB가 양방향으로 유일 대응할 때만 함께 수정 |
| 피아노·신디 | 음정, 쉼표/동시음, 제한된 길이, 가사 | 두 보표·성부·페달 보존; 손·보표 자동 재배정 없음 |
| 드럼 | 원본에서 확인된 타격 종류, 쉼표/동시음, 제한된 길이, 가사 | 음표머리·표시 위치·악기 참조를 함께 변경; 일반 음정으로 오인식된 드럼을 추정하지 않음 |

### 길이와 가사

- 길이는 정확한 유리수 시간으로 계산합니다. 짧게 하면 같은 성부에 쉼표를 채우고, 길게 하면 바로 뒤의 단순 쉼표만 소비합니다. 다른 음표·성부 시작은 옮기지 않습니다.
- 화음·잇단음표·연결 기호·오선/TAB 이중 보표의 복잡한 리듬 수정은 잠급니다.
- 가사 텍스트 수정·새 절 추가·독립 가사 항목 삭제를 지원합니다. 멜리스마·음절 연결은 임의로 끊지 않습니다.
- 직접 드래그, 임의 위치 삽입, 마디·박자·성부·보표 재구성, 복잡하거나 대응이 모호한 연결의 묶음 편집은 미지원입니다. 미지원 기호가 있어도 악보 전체를 삭제·단순화하지 않습니다.

### 연주 기호와 연결

`악센트 · 스타카토 · 테누토`는 여섯 악기의 명확한 음표에 추가·제거할 수 있습니다. `타이 · 슬러 · TAB 연결 주법`은 서버가 확인한 시작/끝 음표 쌍을 사용합니다.

| 연결 | 적용 조건 |
|---|---|
| 타이 | 같은 보표·성부에서 바로 이어지는 같은 음정; 타악기는 같은 명시적 타격 표기 |
| 슬러 | 같은 보표·성부의 뒤쪽 음표 |
| 슬라이드 | 기타·베이스의 같은 줄, 명시된 튜닝·카포·음정이 일치 |
| 해머링 / 풀링 | 위 조건에서 높은 프렛 / 낮은 프렛으로 이동 |

원본 오선+TAB가 양방향으로 유일 대응하면 양쪽 기호를 함께 수정합니다. 음정·길이·가사·다른 파트는 바꾸지 않으며 저장·실행 취소·revision 충돌 방지를 유지합니다.

끝이 없거나 중복된 연결, 복잡한 타이 사슬, 모호한 오선/TAB 대응, 미지원 주법은 추정하거나 끊지 않습니다. 연결 후보는 가까운 뒤쪽 음표로 제한됩니다. 기호 편집을 지원한다고 화음·잇단음표의 리듬 재구성 잠금이 해제되지는 않습니다.

### 드럼·신디의 참조 보존

드럼의 마지막 타격을 쉼표로 바꾼 뒤에도 다시 입력할 수 있도록, 원본에서 확인된 표기 견본을 작업 XML의 명시적 앱 메타데이터에 보관합니다. 최대 64KB·128종이며 악기 정의·견본 체크섬과 XML을 검증합니다. 새 킷은 추정하지 않고 최초 업로드는 바꾸지 않습니다.

다른 악기로 지정된 신디 음표의 악기 참조도 동시음 추가·쉼표 왕복에서 유지합니다.

## 검증·저장·다운로드

| 검사 | 확인하는 것 | 보증하지 않는 것 |
|---|---|---|
| 음악 데이터 일치 확인 | 선택 파트의 XML·악기 정의를 스타일 전후 비교; 위치 정보 외 변경 시 출력 중단 | 원본 PDF 인식 정확도 |
| 악보 구조 점검 | 음표 모양/길이·마디 시간·재생/표시 타이·TAB 튜닝/프렛/음정·드럼 참조 | 인식 누락 없음, 원본 PDF와 같음 |

구조 점검은 읽기 전용입니다. 건반 한 보표·부분 마디·해석하기 어려운 복잡한 표기는 오류로 단정하지 않고 확인 안내로 구분합니다. `해당 위치 확인`으로 마디·음표를 열 수 있습니다. 음표를 자동 수정하거나 없는 악기·가사·음을 채우지 않습니다.

`notes.json`은 선택 파트의 음정·TAB·성부·유리수 시간·편집 가능 범위·검증 해시 인덱스입니다. `integrity_report`에 최대 200개 상세 항목과 전체 건수를 포함합니다. 기준 파일은 여전히 전체 MusicXML이고 JSON 재가져오기는 미지원입니다.

| ZIP | 업로드 원문, 선택 파트 수정본/초기본, 미선택 파트 포함 전체 작업 XML |

## PDF·이미지 인식

`기존 악보 가져와서 스타일 바꾸기 → PDF·이미지 · 악보 인식`에서 일반 오선/드럼을 선택합니다. CPU의 **로컬 Audiveris**로 처리하며 SAM/GPU·외부 업로드는 사용하지 않습니다.

| 입력·실행 | 제한 |
|---|---|
| 형식·업로드 | PDF/PNG/JPG/JPEG, 25MB 이하 |
| PDF | 문서 전체 100페이지 이하; 한 번에 최대 4페이지 지정(예: `1-3,5`) |
| 이미지 | 한 장 2,400만 픽셀 이하 |
| 작업 | 별도 단일 대기열 최대 3개; 진행 상태·취소·시간 제한 |

원본 업로드·선택 페이지 미리보기·모든 MusicXML/MXL 결과를 각각 보관합니다. 사용자가 적용할 결과·파트를 선택하고 **원본 비교 및 인식 한계 확인**을 해야 가져올 수 있습니다.

새 프로젝트에는 원본/결과 SHA256과 출처 링크를 기록합니다. 기존 편집기에 가져오기는 저장 전 초안만 바꾸고, 출처는 별도 OMR 작업에 보관합니다. 기존 편집 문서 자체에 영구 출처를 연결하는 기능은 아직 없습니다.

### PDF 좌표 자료

`pdfplumber`로 문자·벡터 좌표를 먼저 검사합니다. 조건에 맞는 4/6줄 TAB 선과 숫자, 보표 전체 높이를 통과하는 세로선의 마디 경계·숫자 소속을 `source-coordinates.json`으로 보관합니다.

- 경계 순번은 실제 곡의 마디 번호가 아닙니다.
- 이 단계는 스캔 OCR·완성 악보 변환이 아니고 박자·음가·타이·뮤트·주법을 확정하지 않습니다. `editable_musicxml=false`, `rhythm_known=false`이며 모호한 숫자는 그대로 둡니다.
- 리듬 후보는 [별도 선택형 분석](#tab-리듬-후보-읽기)입니다. 좌표 분석 실패 시 경고 후 기존 OMR을 계속합니다.
- 다운로드할 때 등록된 SHA256·크기를 검증합니다.
- 별도 프로세스는 45초(내부 CPU 40초), 최대 4페이지/100페이지 문서, 출력 2MB로 제한합니다. Linux는 AS 1GB를 적용합니다. macOS에서 DATA 제한이 거부되면 경고하며 **완전한 문서 샌드박스는 아닙니다.**

### Audiveris 인식의 알려진 한계

- 음정·쉼표·박자·반복·가사와 드럼 종류를 원본과 대조해야 합니다. 결과는 정답 악보가 아닙니다.
- [TAB 지원 범위](https://audiveris.github.io/audiveris/_pages/guides/specific/tablature/): 4/6줄 TAB 영역을 감지한 뒤 **무시**합니다. TAB의 프렛·줄을 읽지 않으며 오선으로 새 운지를 만드는 것은 원본 운지 복원이 아닙니다.
- [드럼 지원 범위](https://audiveris.github.io/audiveris/_pages/guides/specific/drums/): 1/5선 옵션을 켜도 출판사별 위치·음표머리·GM 매핑 차이가 있습니다. 사용자 지정 `drum-set.xml`과 수동 검수가 필요할 수 있습니다.
- Audiveris 5.11.0은 매 시스템의 타악기 음자리표를 전제로 합니다. 다음 줄에 음자리표가 없으면 일반 음정으로 오인식할 수 있습니다. 앱은 일반 음표 개수와 리듬 불일치 마디 경고를 표시하고 드럼 타격을 임의 배정하지 않습니다.
- 이 버전의 드럼 MIDI 번호가 MusicXML 1 기반 번호와 달라, [호환성 처리](../backend/audiveris_compat.py)는 확인된 버전·GM 이름·악기 ID·번호가 모두 맞을 때만 별도 XML의 번호를 보정합니다. 음표·리듬 수정은 아닙니다. 원본/보정본을 별도 다운로드·SHA256으로 보관하며 모호한 매핑은 추정하지 않습니다. 미보정 결과의 직접 드럼 편집 가져오기도 차단합니다.
- [OCR 언어](https://audiveris.github.io/audiveris/_pages/guides/main/languages/): legacy 호환 tessdata가 없으면 가사·문자 인식이 생략될 수 있습니다. 한글 가사 자동 복원·음원 정렬은 이 기능에 포함되지 않습니다.

실제 드럼 PDF에서 발견한 오류와 검증 범위는 [2026-10-07 검증 기록](research/2026-10-07-score-import.md)에 별도로 정리했습니다.

## PDF TAB 직접 검수

`PDF TAB 숫자 검토 · 기타 / 베이스`는 **Audiveris 없이** PDF 미리보기와 숫자 좌표를 준비합니다. Poppler·`pdfplumber`가 필요하고 SAM/GPU·외부 서비스는 호출하지 않습니다. 실제 문자·선이 있는 PDF가 대상이며 스캔 PDF·윤곽선 숫자 OCR 경로가 아닙니다.

1. `원본 TAB 확인·수정해서 악보 만들기`에서 원본·숫자 위치를 비교합니다. 위쪽 리듬 보표도 함께 보여줍니다. 기본은 첫 TAB 보표 한 개이므로 **출력할 보표를 직접 선택**하세요.
2. 줄·프렛, 실제 마디 번호·시작 위치·길이를 확인합니다. 시작 위치 0은 마디 앞, 1은 항상 4분음표입니다. 점음표·직접 확인한 뮤트·빠진 음 추가·사유를 남기는 후보 제외를 지원합니다.
3. `검수 초안 저장`으로 보관합니다. 선택 보표의 모든 숫자에 사용/제외 결정을 남기고 원본 대조를 확인해야 프로젝트를 만들 수 있습니다.
4. 생성된 **TAB 단일 보표**를 원본 보존 편집기에서 스타일 변경·지원 음표 수정·undo/redo·MusicXML/인쇄 PDF/ZIP 출력에 사용합니다.

새 초안의 **4/4·120 BPM·표준 튜닝은 인식값이 아닌 입력 시작값**입니다. 8/16분음표 연속 배정은 사용자가 선택·확인하는 입력 편의 기능이지 자동 리듬 추정이 아닙니다.

### 검수 범위와 재개

- 4현 베이스/6현 기타, 사용자 지정 튜닝·카포, 최대 2,000개 검토 항목을 지원합니다.
- 같은 줄의 시간 겹침·다른 원본의 초안 적용·검토 항목 누락은 거절합니다.
- 첫 입력 마디부터 출력하고 원래 마디 번호를 유지합니다. 중간에 비운 마디 번호는 쉼표로 남깁니다. 입력 길이가 마디를 넘으면 타이로 나누지만, 이것이 원본 타이를 인식했다는 뜻은 아닙니다.
- 같은 브라우저의 최근 검수 목록은 최대 12개입니다. 작업 ID·제목·상태만 로컬에 보관하며 원본·초안은 서버에 남습니다. 목록 제거는 서버 파일을 지우지 않습니다. 브라우저 저장소 삭제 후 목록 복원·기기 간 동기화는 미지원입니다.
- revision 충돌 시 현재 입력을 유지하고 JSON 백업을 제공합니다.

원본 오선까지 함께 복원하지 않습니다. 가사·반복·코드·슬라이드·벤딩·해머링/풀링의 자동 복원, 변박·잇단음표 검수 입력도 미지원입니다. 생성 후 지원 기호를 직접 추가할 수 있지만 PDF 자동 인식 결과로 취급하지 않습니다.

### 원본과 출력 보관

원본 PDF(`reference.pdf`), 불변 좌표(`source-coordinates.json`), 확인한 입력·출처(`reviewed-tab.json`)를 프로젝트에 복사·해시 검증하고 다운로드·ZIP에 포함합니다. 최초 생성 MusicXML은 원본 PDF와 구분하여 표시합니다.

실패 시 임시 생성물만 정리하고 준비된 프로젝트를 한 번에 공개합니다. 같은 검수 내용의 재시도는 중복 프로젝트를 만들거나 이후 편집본을 덮어쓰지 않습니다.

| API | 용도 |
|---|---|
| `GET/PUT /api/score-omr/{id}/tab-review` | 초안 조회·저장 |
| `POST /api/score-omr/{id}/tab-review/import` | 검수 프로젝트 생성 |
| `POST /api/score-omr/{id}/tab-review/rhythm-suggestions` | 리듬 후보 읽기 |

쓰기 요청은 2MB로 제한합니다. 스타일 내용 비교는 **검수 후 MusicXML 기준**이며 PDF 전체 정확도 판정이 아닙니다.

검수 TAB는 OSMD 1.9의 숫자 전용 기본 표시를 인스턴스별로 보정하여 기둥·점음표·온음표·쉼표를 구분합니다. 원본 XML·박 길이·전역 렌더러는 바꾸지 않으며, 내부 형식이 달라지면 숫자만 정상 결과처럼 보여주지 않고 오류를 표시합니다. 스타일 출력의 마지막 줄도 지정한 폭으로 펼칩니다.

## TAB 리듬 후보 읽기

`오선 표기에서 리듬 후보 자동 읽기 · 검토 후 적용`은 TAB 바로 위에 유일하게 대응하는 5선 보표가 있는 **제한된 벡터 인쇄 형식의 단선율**을 지원합니다.

음표머리·기둥·빔·꼬리·점과 지원하는 타이 윤곽으로 길이를 계산합니다. 숫자의 가로 간격을 음가로 바꾸지 않습니다. 미지원 쉼표·음표머리·다성부·기호, 모호한 숫자 대응, 박자 합계 불일치가 있으면 마디 전체를 보류합니다. 스캔 PDF·오선 없는 TAB·다른 폰트/윤곽에 동일 결과를 보장하지 않습니다.

1. 원본 박자표가 현재 설정과 같음을 체크합니다. 박자표·BPM·튜닝 자체를 인식하는 기능은 아닙니다.
2. `현재 보표의 리듬 후보 읽기`를 요청합니다.
3. 실제 시작 마디 번호를 입력하고, **마디별로 원본과 비교한 뒤 적용**합니다.
4. 화면 초안을 검수·저장하고 최종 원본 대조 확인 후 프로젝트를 생성합니다.

적용은 해당 마디의 화면 초안만 변경하고 직접 고친 줄·프렛은 유지합니다. 자동 일괄 적용·서버 저장·최종 확인·프로젝트 생성을 대신하지 않습니다. API는 원본·좌표 해시, revision, 선택 보표와 확인한 박자를 검사합니다. 미지원 마디는 수동 검수할 수 있습니다.

## 운영·설치

자동 설치나 약관 수락은 하지 않습니다. 기능별 의존성, Audiveris·OCR 언어 설치와 `AKBO_OMR_*` 설정은 [PDF 도구 설치 안내](setup.md#pdf-tools)에 모았습니다. TAB 직접 검수에는 Audiveris가 필요하지 않습니다.

`/api/score-omr/status`에서 의존성 구성을 확인하고 이용 권한이 있는 악보로 실제 인식을 시험합니다. 상태 API는 모델 동작·인식 성공·정확도를 보증하지 않습니다.

서버 재시작으로 중단된 작업은 실패로 표시합니다. `AKBO_DATA_DIR/score-omr/<id>`에는 자동 삭제·유효기간이 없으므로 운영자가 용량·이용 권한을 관리해야 합니다. 현재는 단일 API 프로세스를 전제로 합니다. **공개 배포 전 인증·사용자별 할당량·격리 실행·악성 문서 방어가 별도로 필요합니다.**

## 선택형 격자 편집기로 변환

`고급 · 기존 16분음표 격자 편집기로 변환 → 격자 편집 프로젝트 열기`는 원본 유지와 다른 경로입니다. 표기 유지가 목적이면 기본 원본 보존 경로를 사용하세요.

기존 편집기에서도 파트를 가져올 수 있습니다. 음표·가사·메모·마디 수는 초안에서 대체하고 원본 음원·재생 기준·출력 스타일·최초 생성본은 유지합니다. 저장 전에는 서버를 바꾸지 않고 실행 취소할 수 있습니다. **기존 편집기에서 나중에 가져온 파일은 서버에 원본을 추가 보관하지 않으므로 직접 보관하세요.**

| 항목 | 처리 |
|---|---|
| 지원 시간 | 4분음표 기준 고정 BPM 40~240, 지원 박자의 완전한 마디·변박, 16분음표 격자에 정확히 표현 가능한 600마디 이하 |
| 읽는 항목 | 화음·성부 이동·타이·한 절 가사·줄/프렛·튜닝·카포·기본 연주 표시 |
| 결합 | 오선/TAB 중복 음표와 타이 병합 |
| 건반 | 두 보표 배정을 보존; 음역이 교차해도 위/아래 지정 유지 |
| 재배치 | 원래 보이스 분리·음자리표 변경·이명동음/조표·레이아웃 |
| 거절 | 잇단음표·못갖춘마디·반복·다이내믹·코드/장식음·여러 절/멜리스마 등 보존 불가능한 항목 |

미지원 리듬을 임의로 반올림하지 않습니다. 업로드·압축 해제 크기, 파일 수, XML 요소 수, 숫자 파싱을 제한하고 내부 DTD·엔티티·ZIP 경로 탈출을 거절합니다. 외부 DTD를 내려받거나 MXL 파일을 디스크에 풀지 않습니다.
