## 채보 입력의 스테레오 상쇄 방어

2026-10-07에는 채보 단계의 입력에도 공통 `mono_with_cancellation_guard`를 연결했습니다. 보컬/베이스 pYIN, 경량 드럼 및 전용 ADT의 공유 입력 준비 경로가 대상입니다. 두 채널 평균 전력이 가장 강한 채널의 1% 이하이고 그 채널 RMS가 `1e-5` 이상일 때만 해당 원본 채널을 사용합니다. 정상 녹음은 각 경로의 기존 평균·리샘플·드럼 정규화 순서를 유지하며, 모노/서라운드에서 임의 채널을 고르지 않습니다. 적용 근거는 `channel_preprocessing`에 기록하고 단일 채널 사용 시 반대편의 독립 연주 누락 가능성을 경고합니다. **이 수정은 합산 과정의 심한 입력 손실을 막는 것으로, 드럼 종류 분류·일반 음원의 채보 정확도 개선이나 기존 손실 음원의 복구를 주장하지 않습니다.**

## 웹 기능과 연구 경로의 구분

**사이트에 연결한 기능과 연구용 모델을 구분합니다.** 새 업로드의 분리 방식 선택과 박자 검토 근거는 웹/API에 연결했습니다. 아래 STRUM·CREPE·YourMT3+는 실제 CPU 추론과 비교까지 구현한 **별도 CLI 연구 경로**이며, 웹의 채보 엔진 목록이나 자동 보정에 연결하지 않았습니다. 기존 모델을 일괄 교체할 정확도 근거가 없기 때문입니다.

<a id="stage-1"></a>

## 사이트: 원본에서 각 악기 독립 추출

새 업로드에서 `separation_strategy=independent`를 선택하면 보컬·베이스·드럼·신디·기타·피아노 모두 동일한 준비된 원본의 복사본을 SAM에 전달합니다. 앞 악기를 뺀 잔여 신호를 다음 악기에 쓰는 기존 `sequential`은 기본값으로 유지합니다. 목표는 앞 단계의 과도한 제거가 뒤 악기로 전파되는 영향을 비교하는 것입니다. **독립 추출의 실제 분리 품질 개선은 아직 검증하지 않았습니다.**

독립 결과끼리는 같은 소리가 겹칠 수 있어 합산 보존·잔여 음원을 제공하지 않습니다. 화면과 ZIP 안내에도 이를 명시하며, 믹서는 원본으로 시작하고 분리 결과는 한 악기씩 비교 청취합니다. 분석 전용 업로드와 독립 분리의 잘못된 조합, 추론 중 입력 변조·잘못된 길이·비유한 값, 취소와 중간 실패를 검사합니다. 모의 SAM/API 테스트는 여섯 번의 원본 입력과 중간 실패 시 완료 파일 보존·GPU 정리를 확인했으며 **실제 GPU 재추론은 수행하지 않았습니다.** 기존 프로젝트의 재분리·악보 교체도 자동 실행하지 않습니다.

<a id="stage-2"></a>

## 사이트: 일정 BPM의 적합성과 템포 모호성

`BPM · 박 위치 분석`에 전체 박열의 일정 격자 적합, 반속/배속 후보, 구간별 주기 변화, 기존 분석 추천 BPM의 누적 밀림 근거를 추가했습니다. 일정한 박열이 충분히 확인될 때만 별도 정수 BPM 비교 버튼을 제공합니다. 박 간격이 불규칙하거나 구간이 짧으면 후보를 거절하며, **BPM·마디 첫 박·기존 악보는 자동 변경하지 않습니다.** 주기성·격자 잔차는 정확도나 정답 다운비트가 아닙니다. 변속 템포 지도·셋잇단음표의 악보 반영은 아직 별도 과제입니다.

고정 100/137 BPM 합성 클릭에서 정밀 후보를 확인했고, 90→120 BPM 변화에서는 일정 BPM을 강제하지 않도록 검사했습니다. 사용자 곡의 원본/분리 드럼 앞 180초는 종전 추천 99 BPM을 유지했습니다. 박열 적합은 약 100 BPM이지만 95백분위 잔차가 각각 약 .104/.096초로 커서 **정밀 후보를 거절**했습니다. 이 결과로 기존 악보의 미검수 120 BPM을 100으로 바꾸지 않았습니다. 기록: `.data/rhythm-research-20261006/final-v1/report.json`.

## 독립 인식기: 실제 추론 결과와 도입 판단

공식 소스·모델 자료를 조사하고 [STRUM](https://github.com/opria123/strum), [CREPE/torchcrepe](https://github.com/maxrmorrison/torchcrepe), [YourMT3+](https://github.com/mimbres/YourMT3)를 별도 환경에서 실행했습니다. 같은 ADT 모델의 3회 문맥 분석과 달리 독립된 모델 비교입니다. 소스/가중치 버전과 해시를 고정하고, 추론 전후 입력·구현 무결성을 검사합니다. 외부로 사용자 음원을 보내지 않으며 결과 파일은 새 경로에만 생성합니다. 다운로드된 모델·음원·런타임은 Git에서 제외합니다.

| 경로 | 이번 실제 비교 결과 | 적용 결정 |
| --- | --- | --- |
| STRUM 2단계 드럼 인식 | 기존 MDB 10곡의 14조건 재사용. 공통 5계열 온셋 ±50ms F1: 드럼 단독 .8830→.7759, 원본 믹스 .4571→.6257, 전체 .7506→.7323 | 원본 믹스에서 이점이 있지만 드럼 단독에서 회귀. 기본 교체하지 않음 |
| 독립 모델이 확인한 하이햇 후보 | ADT의 기존 1/3표 탈락 후보만 STRUM과 대조. 53개 제안 중 kit-11 기준 정답 +37, 추가 오류 +16 | 검토 JSON만 생성. 악보에 자동 추가하지 않음 |
| CREPE 보컬·베이스 | 합성 저음 베이스 정답 4/6→6/6, 비브라토 보컬 추가 오류 5→3. 반면 기본 베이스 정답 8→6 | 개선/회귀 공존. 기존 pYIN 유지 |
| YourMT3+ 여섯 악기 | 재사용 합성 15조건과 실제 원곡/분리 파트 비교. 기타 화음 일부 개선, 다른 조건 회귀·악기 분류 혼동 확인 | 원시 악기 분류를 보존하는 비교용 CLI. 파트 이름에 맞춰 음표를 강제 변환하지 않음 |

STRUM 비교의 원본 믹스 4개는 같은 10곡 중 일부이며 **14개의 독립 곡/새 검증 세트가 아닙니다.** 드럼 단독은 데이터셋 제공 녹음으로 SAM 결과도 아닙니다. 하이햇 검토 정책 역시 탐색 실험이며 일반화 검증이 아닙니다. STRUM은 하이햇 개방/폐쇄·페달을 구분하지 못하고, 원본 게임 차트 생성기의 규칙 채우기·양자화는 가져오지 않았습니다. 세부 구현·출처·측정 조건·재실행 명령은 [드럼 독립 모델 연구 기록](../drum-challenger-research.txt)에 있습니다.

사용자 곡 앞 12초의 분리 드럼은 ADT 하이햇 31개/첫 .893초, STRUM 36개/첫 .871초였습니다. 원본 믹스에서는 각각 10개/5.368초, 14개/1.776초였습니다. 검토 CLI는 4개 후보를 추가 제안하지만 **.87초 이전 하이햇 누락을 복구하지 못했습니다.** 현재 곡의 사람이 확인한 정답이 없으므로 개수 증가는 정확도 개선이 아닙니다. 실제 기타 분리 입력을 YourMT3가 드럼으로, 베이스 입력을 기타로 인식하는 차이도 확인했지만, 이것만으로 분리 누설과 새 모델의 오분류 중 어느 쪽이 원인인지 확정할 수 없습니다.

선택형 런타임은 Python 3.11의 별도 가상 환경에 설치합니다. 기존 앱 환경에 연구 의존성을 합치지 마세요. CREPE는 `requirements-crepe.txt`, YourMT3+는 `requirements-yourmt3.txt`, STRUM은 `requirements-drum-challenger.txt`를 사용합니다. 준비 단계만 다운로드하며 이후 추론은 로컬에서 수행합니다. YourMT3+는 공식 Space의 고정 소스/체크포인트를 검사하고 검증된 임시 소스에서 실행합니다.

```sh
# 각각 준비된 별도 가상 환경을 사용하는 예시. 출력은 존재하지 않는 새 경로여야 합니다.
.data/pitched-runtime/.venv/bin/python scripts/transcribe-melody-challenger.py \
  --audio /path/to/vocal.wav --instrument vocal --output .data/new-vocal-review.json
.venv/bin/python scripts/prepare-yourmt3.py --runtime .data/yourmt3-runtime
.data/yourmt3-runtime/.venv/bin/python scripts/transcribe-yourmt3.py \
  --runtime .data/yourmt3-runtime --audio /path/to/excerpt.wav --output .data/new-yourmt3-review
```

로컬 근거: `.data/strum-research-20261006/{evaluation,rescue-evaluation,summary}.json`, `user.review.final.json`; `.data/pitched-crepe-20261006/final-{development,validation}-v2/report.json`; `.data/pitched-yourmt3-20261006/paired-v1/report.json`, `actual20-32/report.json`. 최종 안전성 보완 후 실제 추론/검토를 재실행해 이전 음표·확률 또는 4개 검토 후보가 동일함을 확인했습니다. ADTOF·Separate-and-Detect 등 추가 후보는 조사만 했고 도입하지 않았으며, SDX 2023도 기존 요청대로 도입하지 않았습니다.

최종 검증: 실제 pYIN을 포함한 서버 **1,411개 통과·8개 별도 실행 제외**, 프런트 **97개 통과**, TypeScript/Vite 빌드 통과. 별도 실제 ADT CPU 통합 검사 **6개 통과**. Orca 브라우저에서 새 분리 옵션/분석 전용 숨김을 확인했고, 별도 로컬 프로젝트의 실제 12초 원본으로 박자 분석→근거/경고 표시→BPM 120·오프셋 0 유지, 가로 넘침 없음과 콘솔 오류 없음을 확인했습니다. 화면 캡처도 정상 확인했습니다. 회사 서버에는 음원 조회만 수행했으며, 배포·SAM/GPU 재추론·기존 악보 덮어쓰기·Git 푸시는 하지 않았습니다.

## 당시 남은 개발 과제

아래는 이 연구 단계에서 남긴 과제입니다. 이후 PDF/편집기 구현을 포함한 현재 범위는 [로드맵](../roadmap.md)을 확인하세요.

1. 정확성 우선: 독립 모델 실제 비교까지 진행했으나 사용자 곡의 도입부 하이햇 누락은 미해결. 실제 오류 구간의 검수된 정답, 더 넓은 독립 평가, 실제 SAM 순차/독립 추출 A/B가 우선입니다. 하이햇 음색·개방 구분과 실제 분리 아티팩트에 맞춘 학습/보정, 피아노 전용 모델 등 악기별 후보를 이어서 비교해야 합니다. 모델 간 동의만으로 정답을 확정하지 않으며, 검토 후보의 웹 비교/개별 적용은 별도 구현이 필요합니다. 기타 배음·안쪽 화음·신디 지속음·코러스·운지도 실제 연주 기준으로 검증합니다.
2. 구간별 주기 변화 진단은 구현했지만 템포 지도/다운비트·정밀 음표 길이·쉼표 정리의 자동 악보 반영은 남았습니다. 16분음표 격자로 표현하지 못하는 셋잇단음표·못갖춘마디·독립 성부를 함께 확장합니다.
3. 사용자 보유/이용 가능한 MusicXML을 우선 기준 악보로 받아 스타일 재조판 → 오디오 정렬 → 차이 검토. PDF OMR 업로드와 실제 엔진 1페이지 검증은 완료했으나 드럼/리듬/가사 인식 오류가 남아 수동 검수가 필요함. 출처/이용 조건을 확인한 악보 검색은 아직 자동화하지 않음.
