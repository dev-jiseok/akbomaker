# 악보 메이커

음악을 악기별로 나누어 악보 초안을 만들고, 기존 악보는 **음악 내용을 유지하면서 읽기 편한 스타일로 바꾸는** 웹 작업실입니다.

React · TypeScript · FastAPI · Python 3.11 · SAM Audio

[설치·서버 운영](docs/setup.md) · [악보 편집](docs/score-editing.md) · [기존 악보 가져오기](docs/score-import.md) · [날짜별 업데이트](CHANGELOG.md) · [전체 문서](docs/README.md)

> 정확성과 가독성을 우선합니다. 자동 채보와 PDF 인식 결과는 **확인·수정이 필요한 초안**이며, 모든 곡과 악보의 정확한 변환을 보장하지 않습니다.

## 두 가지 작업 방식

| 하고 싶은 일 | 메뉴 | 흐름 |
| --- | --- | --- |
| 음악에서 새 악보 만들기 | 음악 작업실 | 파일/YouTube → 악기 분리 → 채보 → 확인·수정 → 출력 |
| 가지고 있는 악보의 스타일 바꾸기 | 악보 스타일 변환 | MusicXML/PDF/이미지 → 원본 비교 → 스타일 변경 → 필요한 부분 수정 → 출력 |

기존 악보 가져오기는 음원 분리와 별도 기능입니다. **MusicXML은 음악 데이터를 직접 보존**하고, PDF·이미지는 인식·검수 과정이 먼저 필요합니다.

## 주요 기능

| 분야 | 지원 내용 | 확인할 점 |
| --- | --- | --- |
| 악기 분리 | 보컬·베이스·드럼·신디·기타·피아노, 순차/원본 독립 분리 | SAM 모델 승인·GPU 필요. 독립 스템은 서로 겹칠 수 있음 |
| 악기별 악보 | 보컬 멜로디, 기타·베이스 TAB 우선, 피아노·신디 대보표, 드럼 5선 | 악기별 인식 오류와 누락은 직접 검토 |
| 편집·가사 | 음표/TAB/드럼/가사 수정, 실행 취소, 가사·보컬 진입 위치 | 음원에서 생성한 격자 악보와 원본 보존 악보의 편집 범위가 다름 |
| 원본 악보 스타일 | MusicXML 파트 선택, 원본/수정본 보관, 스타일 전후 음악 내용 비교 | PDF 인식 정확도를 보증하는 비교는 아님 |
| PDF TAB 검수 | 숫자·줄·프렛 확인, 초안 저장·재개, 마디별 리듬 후보 | 지원하는 벡터 오선+TAB 형식에 한정. 후보는 검토 후 적용 |
| 재생·출력 | 원본/분리 음원 비교, 합성음 미리듣기, 스타일·2/4마디 배치, 인쇄/PDF | 오디오 프로젝트는 WAV·MIDI·MusicXML·ZIP, 원본 보존 프로젝트는 MusicXML·자료 ZIP |

세부 동작은 [악보 편집 가이드](docs/score-editing.md), [악보 가져오기 가이드](docs/score-import.md), [악기별 엔진 안내](docs/audio-engines.md)를 참고하세요.

## 빠른 시작

모든 명령은 저장소 루트에서 실행합니다. 설치 방식은 서버용과 GPU 없는 개발용 중 하나를 선택하세요.

### GPU 서버

Linux NVIDIA 서버에 nvm·uv·Git·FFmpeg와 호환 드라이버가 필요합니다. SAM 모델 접근 승인을 받은 계정의 인증도 먼저 준비하세요.

```sh
./start.sh --host 127.0.0.1 --port 8000
```

- 접속: <http://127.0.0.1:8000>
- 초기 실행은 모델 다운로드·엔진 준비 검사 때문에 시간이 걸립니다.
- PDF 기능의 추가 의존성과 외부 접속/배포 설정은 [설치·서버 운영](docs/setup.md)을 확인하세요.
- **GitHub에 머지됐다고 회사 서버에 자동 배포되는 것은 아닙니다.** 서버 권한이 있는 운영자가 반영해야 합니다.

### GPU 없이 샘플·개발 화면

Node 22·Python 3.11·uv·FFmpeg를 준비한 뒤 실행합니다.

```sh
npm ci
uv venv --python 3.11
uv pip install -r backend/requirements-dev.txt
```

터미널 1 — API:

```sh
AKBO_ALLOW_DEGRADED=1 .venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

터미널 2 — 웹:

```sh
npm run dev
```

접속: <http://127.0.0.1:5173> · API 문서: <http://127.0.0.1:8000/docs>

이 모드는 엔진 준비 검사를 명시적으로 생략합니다. **샘플은 SAM 분리 결과가 아니며**, GPU 없는 상태에서 실제 악기 분리가 가능한 것으로 표시하지 않습니다. CPU 가사 인식과 PDF 인식은 각각 [추가 설정](docs/setup.md)이 필요합니다.

## 지원 입력

- **음악·영상:** MP3, WAV, FLAC, M4A, AAC, OGG, OPUS, MP4, MOV, WEBM, MKV, AIFF/AIF. 기본 최대 200MB·10분.
- **YouTube:** 개별 영상 링크. 로그인·쿠키·라이브·재생목록·보호된 영상은 지원하지 않습니다.
- **기존 악보:** MusicXML/XML/MXL 최대 2MB. PDF/PNG/JPG 최대 25MB·한 번에 최대 4페이지.
- 직접 제작했거나 이용 권한이 있는 파일을 사용해주세요.

## 현재 한계

- 드럼 하이햇 누락·킥 혼동, 화음·지속음·코러스 등의 자동 인식 오류가 남아 있습니다. 음표 수 증가나 모델 간 동의는 정확도 증거가 아닙니다.
- 음원 채보의 기본 시간 표현은 고정 BPM·16분음표 격자입니다. 자동 템포 지도·다운비트·독립 성부 인식은 미완성입니다.
- 원본 MusicXML의 복잡한 표기를 보존하는 것과 직접 편집하는 것은 다릅니다. 모든 기호를 편집하거나 동일하게 렌더링하지는 못합니다.
- PDF·스캔 악보를 같은 음·TAB로 완전히 자동 복원하는 기능은 미완성입니다. 스타일 변경이 인식 오류를 고쳐주지는 않습니다.
- 개인 작업실용 구성입니다. 공개 서비스의 인증·사용자별 권한·보관 정책·격리 실행은 별도 운영 확장이 필요합니다.

남은 기능은 [개발 과제](docs/roadmap.md), 검증 방법과 실제 확인 범위는 [테스트 안내](docs/testing.md)에 정리했습니다.
